Task 2: Feature Extraction

Dense embeddings with DINOv3

DINOv3 ViT-S/16 Architecture

  • Patch embedding: 16×16 patches → 384-dim tokens via linear projection
  • Transformer encoder: 12 layers, 6 heads, MLP ratio 4
  • Position encoding: RoPE (Rotary Position Embeddings) — relative position baked into attention
  • Register tokens: 4 extra tokens that absorb global/positional artifacts (in theory!!)
  • Training: DINO self-supervised loss (student-teacher with EMA)
  • Output: CLS token + per-patch tokens (384-dim each)

Larger variants: ViT-B (768-dim, 12 heads), ViT-L (1024-dim, 16 heads), ViT-H (1280-dim), ViT-7B (4096-dim)
Also available: ConvNeXt backbones (hierarchical, 32× stride, no RoPE)

Patch Size Selection

  • DINOv3 ViT uses 16×16 patches
  • Downsample to s1 (1/2 size) so smallest mitochondria are around 20px.
  • We guess detection will be easier if patch has good chunk of mito.
  • Captures texture but not full geometry
  • Probably could do something fancier like Fourier matching to Instagram training data?
  • Or treat scale as hyperparam to optimize (expensive)

Positional Encoding Challenges

  • DINOv3 uses RoPE (Rotary Position Embeddings)
  • Bakes position into Q/K at every attention layer
  • Creates a spatial gradient in embeddings (red→blue across image)

Solution to RoPE: Translated Passes

  • Native ViT stride = 16 → coarse grid
  • Run model at multiple (dy, dx) offsets i.e. `Tinv(f(T(x))) for T in Translations`.
  • Average across translation passes.
  • stride=4 → 16 passes, stride=2 → 64 passes

Without background subtraction

With empirical subtraction

Why Not Hack the Stride?

  • Setting model.patch_embed.proj.stride = (4,4) produces overlapping patches in one pass
  • But creates high-frequency artifacts — model wasn't trained for overlap
  • Translated passes give smoother, more consistent results
  • Each pass sees the image as the model expects: non-overlapping 16×16 patches

Task 3: Embedding-Based Retrieval

Can we find mitochondria using a single query?

Retrieval Approach

  1. Select mito centerpoints as query locations
  2. Extract query embedding at each point
  3. Compute cosine similarity against all target embeddings
  4. Average (max?) similarity maps across multiple queries
for qemb in query_embs:
    sim_accum += (tokens_normed @ qemb.T).squeeze(-1).numpy()
sim_accum /= len(query_embs)
